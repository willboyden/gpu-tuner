History

Left out on purpose

The driver exposes more than this page does. These were excluded because a wrong value cannot be made safe by clamping it.

Core and memory clock offsets (overclock / undervolt)
The driver accepts a wide offset range on most cards, but no range of offsets is known-stable across arbitrary hardware, and on an inference and fine-tuning box an unstable offset shows up as quietly wrong results or Xid faults rather than a clean crash.
Raising the thermal limits or a temperature target
Not supported on most cards (NVML reports the acoustic thresholds as unsupported). Each card's own slowdown and shutdown points, whatever they are, stay put — this page reads them, never writes them.
Toggling ECC, MIG or compute mode
ECC mode and its error counts are shown read-only when a card supports them; toggling ECC needs a reboot and changes usable VRAM, and MIG/exclusive-process mode can break other software sharing the card. None of these three is offered as a write.
Turning persistence mode off
Held on by the daemon (its actual on/off state is shown read-only). With it off, the driver drops the power caps whenever the last CUDA client exits.
Chassis fans
On this lab's own board they're BMC-owned and the motherboard's PWM registers do nothing; whether that's true elsewhere depends on the board, so this stays out of scope everywhere.
